Card

A padded surface with a shadow. The classless build styles every article this way; .card in 1.x meant the bordered variant, which is now .card-border.

ClassDoes what
cardPadded, raised surface with a shadow
card-borderFlat surface with a border instead of a shadow
card-actionsFooter row: top border, right-aligned actions

Basic

<article class="card prose">
  <h3>Card heading</h3>
  <p>Cards hold a block of related content.</p>
</article>
<article>
  <h3>Card heading</h3>

</article>

With a footer

<article class="card prose">
  <h3>Delete this project?</h3>
  <p>This cannot be undone.</p>
  <footer class="card-actions flex" style="justify-content: end">
    <button class="btn btn-secondary">Cancel</button>

</article>

Bordered

<div class="card-border prose">
  <h3>Bordered</h3>
  <p>A border instead of a shadow, on the page background.</p>
</div>
<div class="card-border">
  <h3>Bordered</h3>
  <p>A border instead of a shadow, on the page background.</p>
</div>

In 1.x, .card was the bordered variant. Both builds now share one set of class names, so .card is the base card and the bordered one is .card-border.

Composition

Common ways to put this together with other components. The general rules are on Composition.

A grid of equal cards and a call to action

Several offers of equal weight, then one card that asks for the next step.

Same markup in both builds 
<section class="prose">
  <h2>Services</h2>
  <div style="display: grid; grid-template-columns: repeat(auto-fit, minmax(min(100%, 16rem), 1fr)); gap: var(--padding); margin-bottom: 1rem">
    <article class="card"><h3>First service</h3><p>What it is, in a line.</p></article>
    <article class="card"><h3>Second service</h3><p>What it is, in a line.</p></article>
    <article class="card"><h3>Third service</h3><p>What it is, in a line.</p></article>
  </div>
  <article class="card" style="text-align: center">
    <p>Not sure which fits?</p>
    <a href="#" class="btn">Talk it through</a>
  </article>
</section>
  • Layout: a grid with min(100%, 16rem) columns: as many as fit, one on a phone, and never wider than the screen.
  • Spacing: .prose does not space a div, so the grid carries its own 1rem bottom margin before the call to action.

Bordered items in a raised card

A card holding a few bordered blocks: the blocks drop back to the page colour, which separates them without a second shadow.

Same markup in both builds 
<article class="card prose">
  <h3>Downloads</h3>
  <div style="display: grid; grid-template-columns: repeat(auto-fit, minmax(min(100%, 10rem), 1fr)); gap: var(--padding)">
    <div class="card-border"><strong>Logo</strong><p class="flex"><a href="#" class="link">SVG</a> <a href="#" class="link">PNG</a></p></div>
    <div class="card-border"><strong>Flyer</strong><p class="flex"><a href="#" class="link">PDF</a></p></div>
  </div>
</article>
  • Surface: surfaces are solid, so a .card inside a .card would be invisible. .card-border is the nested surface.
