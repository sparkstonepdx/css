Tabs

Layered panels with one visible at a time. The classes are shaped around Kobalte's rendered markup, so state comes from its data-* attributes. Drive the markup yourself and .tab-active does the same job.

ClassDoes what
tabsThe tab list: a row with a bottom rule. Put it on Tabs.List
tabA tab button. Put it on Tabs.Trigger
tab-indicatorThe sliding underline. Put it on Tabs.Indicator
tab-contentA tab panel. Put it on Tabs.Content
tab-activeMarks the selected tab when no headless library sets data-selected

Basic

Kobalte sets data-selected on the selected trigger and positions the indicator, so the CSS only has to react to it. 

<div>
  <div class="tabs" role="tablist">
    <button class="tab" role="tab" id="t-profile" aria-controls="p-profile" data-selected>Profile</button>
    <button class="tab" role="tab" id="t-dashboard" aria-controls="p-dashboard">Dashboard</button>
    <button class="tab" role="tab" id="t-settings" aria-controls="p-settings">Settings</button>
    <div class="tab-indicator"></div>
  </div>
  <div class="tab-content" role="tabpanel" id="p-profile" aria-labelledby="t-profile">Profile details</div>
  <div class="tab-content" role="tabpanel" id="p-dashboard" aria-labelledby="t-dashboard" hidden>Dashboard details</div>
  <div class="tab-content" role="tabpanel" id="p-settings" aria-labelledby="t-settings" hidden>Settings details</div>
</div>
import { Tabs } from "@kobalte/core/tabs";

<Tabs aria-label="Account" defaultValue="profile">
  <Tabs.List class="tabs">
    <Tabs.Trigger class="tab" value="profile">Profile</Tabs.Trigger>
    <Tabs.Trigger class="tab" value="dashboard">Dashboard</Tabs.Trigger>
    <Tabs.Trigger class="tab" value="settings">Settings</Tabs.Trigger>
    <Tabs.Indicator class="tab-indicator" />
  </Tabs.List>
  <Tabs.Content class="tab-content" value="profile">Profile details</Tabs.Content>
  <Tabs.Content class="tab-content" value="dashboard">Dashboard details</Tabs.Content>
  <Tabs.Content class="tab-content" value="settings">Settings details</Tabs.Content>
</Tabs>

Without an indicator

Leave Tabs.Indicator out and the selected tab draws its own underline instead. The rule is .tabs:not(:has(.tab-indicator)), so you never get both. 

<div>
  <div class="tabs" role="tablist">
    <button class="tab" role="tab" id="t2-week" aria-controls="p2-week" data-selected>This week</button>
    <button class="tab" role="tab" id="t2-month" aria-controls="p2-month">This month</button>
  </div>
  <div class="tab-content" role="tabpanel" id="p2-week" aria-labelledby="t2-week">7 new sign-ups</div>
  <div class="tab-content" role="tabpanel" id="p2-month" aria-labelledby="t2-month" hidden>34 new sign-ups</div>
</div>
<Tabs defaultValue="week">
  <Tabs.List class="tabs">
    <Tabs.Trigger class="tab" value="week">This week</Tabs.Trigger>
    <Tabs.Trigger class="tab" value="month">This month</Tabs.Trigger>
  </Tabs.List>
  <Tabs.Content class="tab-content" value="week">7 new sign-ups</Tabs.Content>
  <Tabs.Content class="tab-content" value="month">34 new sign-ups</Tabs.Content>
</Tabs>

Disabled

Kobalte sets data-disabled on a disabled trigger. The tab greys out the same way a disabled button does, and stops taking pointer events. 

<div>
  <div class="tabs" role="tablist">
    <button class="tab" role="tab" id="t3-a" aria-controls="p3-a" data-selected>Details</button>
    <button class="tab" role="tab" id="t3-b" aria-controls="p3-b" data-disabled>Billing</button>
  </div>
  <div class="tab-content" role="tabpanel" id="p3-a" aria-labelledby="t3-a">Available on every plan</div>
  <div class="tab-content" role="tabpanel" id="p3-b" aria-labelledby="t3-b" hidden>Upgrade to see billing</div>
</div>
<Tabs defaultValue="details">
  <Tabs.List class="tabs">
    <Tabs.Trigger class="tab" value="details">Details</Tabs.Trigger>
    <Tabs.Trigger class="tab" value="billing" disabled>Billing</Tabs.Trigger>
  </Tabs.List>
  <Tabs.Content class="tab-content" value="details">Available on every plan</Tabs.Content>
  <Tabs.Content class="tab-content" value="billing">Upgrade to see billing</Tabs.Content>
</Tabs>

Vertical

Kobalte puts data-orientation on every part, so the list turns into a column and the indicator moves to the trailing edge without any extra class. 

<div style="display: flex; gap: 1rem" data-orientation="vertical">
  <div class="tabs" role="tablist" aria-orientation="vertical" data-orientation="vertical">
    <button class="tab" role="tab" id="t4-a" aria-controls="p4-a" data-selected>General</button>
    <button class="tab" role="tab" id="t4-b" aria-controls="p4-b">Members</button>
    <div class="tab-indicator" data-orientation="vertical"></div>
  </div>
  <div class="tab-content" role="tabpanel" id="p4-a" aria-labelledby="t4-a">General settings</div>
  <div class="tab-content" role="tabpanel" id="p4-b" aria-labelledby="t4-b" hidden>Member settings</div>
</div>
<Tabs orientation="vertical" defaultValue="general" style="display: flex; gap: 1rem">
  <Tabs.List class="tabs">
    <Tabs.Trigger class="tab" value="general">General</Tabs.Trigger>
    <Tabs.Trigger class="tab" value="members">Members</Tabs.Trigger>
    <Tabs.Indicator class="tab-indicator" />
  </Tabs.List>
  <Tabs.Content class="tab-content" value="general">General settings</Tabs.Content>
  <Tabs.Content class="tab-content" value="members">Member settings</Tabs.Content>
</Tabs>

Without Kobalte

The same classes work on plain markup. Use .tab-active for the selected tab and .tab-disabled for a disabled one, and wire the clicks yourself. 

<div class="tabs" role="tablist">
  <button class="tab tab-active" role="tab" aria-controls="panel-1">One</button>
  <button class="tab" role="tab" aria-controls="panel-2">Two</button>
</div>
