@sparkstone/css

A lightweight SCSS framework in the spirit of Pico.css and daisyUI, rebuilt on oklch() relative color syntax. Give it one base color and it derives an entire light and dark palette that clears WCAG AA on every pairing the framework uses.

Quickstart · npm · GitHub

Two builds, one source

Every component is defined once, as a class. The classless build emits those same classes and then binds them to plain elements with Sass @extend, which is the native version of Tailwind's @apply: button { @extend .btn; } compiles to .btn, button { ... }. One rule, both builds, no drift. The classless build carries the class names too, so you can mix the two.

BuildImportStyles
Class @sparkstone/css Class names only, following daisyUI 5. Plain elements are left alone.
Classless @sparkstone/css/classless Semantic HTML, no classes needed. This is the 1.x theme, unchanged.

Every component page below shows both, side by side. Switch the tab on any example to see the other build, and the preview switches stylesheets with it.

What you get

  • A nine-step perceptual scale derived from a single --color.
  • Light and dark from the same scale, mirrored. No second palette to maintain.
  • daisyUI 5 class names, with dialog-* in place of modal-*.
  • No JavaScript for any core styling.
  • Sass functions and mixins when you need to reach past the defaults.

Theming

Three colors drive everything. Set them anywhere a CSS variable can be set.

:root {
  --color: rebeccapurple;
  --accent-color: oklch(from var(--color) l c calc(h + 180));
  --error-color: maroon;
}

Because they are plain CSS variables, you can rebind --color on a subtree and every descendant recolors itself. See Colors and Customizing.

Light and dark

The scheme follows prefers-color-scheme by default. Force it with an attribute on any element, not just <html>: 

<html data-color-scheme="light">
<html data-color-scheme="dark">

Live preview

Change these and every page on this site updates. Values persist for the session.

Browser support

The framework leans on relative color syntax, oklch(from ...). That means Chrome 119+, Safari 16.4+, and Firefox 128+. There is no fallback layer, by design.
