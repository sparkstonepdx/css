Notice

The phone's toast. Notices open low, just above the dock, where the thumb and the eyes already are, and stack upward. How long each stays and showing one at a time come from @sparkstone/kit.

alpha The class names and states here are stable. The look is not: these styles can change in a minor release, without a major version bump.

ClassDoes what
noticesThe stack, fixed above the dock (reads --dock-h)
noticeOne message: an edged card on a tint
notice-successSomething worked
notice-warningSomething to be careful about
notice-errorSomething went wrong
notice-artThe thing it's about, in a coin
notice-textA bold line and an optional detail in <small>
notice-actionsUndo, Edit
notice-linkThe whole notice is one link, on its text
notice-goThe › at the end of a link

Basic

The stack is shown in place here rather than fixed to the bottom.

Same markup in both builds 
<ul class="notices" style="position: static; padding: 0">
  <li class="notice">
    <span class="notice-art" aria-hidden="true">🍼</span>
    <span class="notice-text"><strong>Logged bottle 90 ml</strong><small>Use by 12:11 PM</small></span>
    <span class="notice-actions"><button class="btn btn-sm">Undo</button></span>
  </li>
  <li class="notice notice-success">
    <span class="notice-text"><strong>Invite link copied</strong></span>
  </li>
  <li class="notice notice-warning">
    <span class="notice-text"><strong>Syncing…</strong><small>Your changes are saved on this phone.</small></span>
  </li>
  <li class="notice notice-error">
    <span class="notice-text"><strong>The server isn't answering.</strong><small>Your moves go through once it's back.</small></span>
  </li>
</ul>

Link

A notice that goes somewhere: the link sits on its text and covers the whole notice, with a › at the end. Buttons in it still take their own taps.

Same markup in both builds 
<ul class="notices" style="position: static; padding: 0">
  <li class="notice notice-link">
    <span class="notice-text"><a href="#"><strong>Your turn in another game</strong></a></span>
    <span class="notice-go" aria-hidden="true">›</span>
  </li>
  <li class="notice notice-link">
    <span class="notice-art" aria-hidden="true">🏔️</span>
    <span class="notice-text"><a href="#"><strong>Sam reached the summit</strong></a><small>See the climb</small></span>
    <span class="notice-go" aria-hidden="true">›</span>
  </li>
</ul>

Styling to fit the app

Every part of a notice's look is a token, so an app sets a few on :root instead of overriding rules: --notice-edge, --notice-bg, --notice-ink, --notice-muted, --notice-weight, --notice-width, --notice-pad, --notice-radius, --notice-shadow, --notice-art-size, --notice-art-bg, --notice-art-ink. The default is a card as wide as its words, edged in the accent on a tint of it.

Same markup in both builds 
<ul class="notices" style="position: static; padding: 0; --notice-edge: oklch(0.72 0.14 80)">
  <li class="notice"><span class="notice-text"><strong>A gold edge (Wordbag): --notice-edge</strong></span></li>
</ul>
<ul class="notices" style="position: static; padding: 0; margin-top: 1rem; --notice-edge: var(--line); --notice-bg: var(--surface); --notice-weight: 700; --notice-width: 100%; --notice-art-size: 2.5rem; --notice-art-bg: var(--accent); --notice-art-ink: var(--accent-ink)">
  <li class="notice"><span class="notice-art" aria-hidden="true">🍼</span><span class="notice-text"><strong>A plain card, full width, bold, with a coin</strong><small>--notice-edge, -bg, -weight, -width, -art-size, -art-bg</small></span></li>
</ul>
